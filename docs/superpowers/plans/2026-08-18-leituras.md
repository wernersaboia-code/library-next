# Página Leituras — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Dar aos livros lidos e abandonados um lugar próprio na navegação — uma página `/leituras` com duas abas — conforme `docs/superpowers/specs/2026-08-18-leituras-design.md`.

**Architecture:** Duas consultas novas em `lib/db/queries.ts`, irmãs de `fetchFavorites`, reusando `colunasDaEstante` e `LivroDaEstante` sem alteração. Uma página de servidor (`app/(main)/leituras/page.tsx`) escolhe a consulta pelo query param `aba` e entrega a lista à `Estante` existente. A navegação passa a ter uma única fonte de verdade: `HREFS_BARRA` muda de `mobile-tab-bar.tsx` para `nav-bar.tsx`, ao lado de `LINKS`, e o menu "Mais" deriva seus itens de `LINKS` menos `HREFS_BARRA` em vez de repetir as rotas à mão.

**Tech Stack:** Next.js 15 (App Router, Server Components), React 19, Drizzle ORM sobre Postgres (Supabase), Tailwind CSS, lucide-react, Vitest.

## Global Constraints

- Nomes de variável, comentários e mensagens de commit em **português**, prefixo `type:` minúsculo (`feat:`, `docs:`), no estilo do `git log` existente.
- **Nenhuma migração, coluna nova ou rota de API.** A feature é só leitura sobre colunas existentes (`read_status`, `date_finished`).
- **Não usar `pnpm typecheck` / `pnpm lint` / `pnpm test` neste ambiente**: o wrapper de checagem de dependências do pnpm falha espuriamente. Chamar os binários direto: `./node_modules/.bin/tsc --noEmit`, `./node_modules/.bin/eslint . --ignore-pattern ".claude/**"`, `./node_modules/.bin/vitest run`.
- ESLint deste projeto proíbe **non-null assertion** (`@typescript-eslint/no-non-null-assertion: 'error'`) — nunca escrever `x!`.
- `tsconfig.json` **não** tem `noUncheckedIndexedAccess`: acesso indexado a um `Record` tipa como não-nulo, então uma chave ausente vira erro em execução, não de tipo. Todo acesso por chave dinâmica precisa de fallback explícito (`?? Padrao`).
- Sem framework de teste de componente no repo: a verificação de UI é typecheck + lint + uso real no navegador. Testes automatizados só para as consultas.
- O breakpoint mobile/desktop é `md` (768px), como em todo o app.
- Servidor de desenvolvimento: já existe um rodando em `http://localhost:3002` para este checkout. Navegar direto para a URL — **não** usar `preview_start` com nome de `launch.json`, que neste ambiente resolve para o diretório errado.

- [ ] **Step 3: Implementar as duas consultas**

Em `lib/db/queries.ts`, logo **depois** da função `fetchFavorites` (e antes do comentário `// — Painel (estatísticas) —`), acrescentar:

```ts
/**
 * O histórico de leitura: o que já foi terminado.
 *
 * Ordem cronológica inversa — o que se acabou de ler vem primeiro. `nulls
 * last` é o ponto todo: por padrão o Postgres põe NULL no topo de um DESC, e
 * como boa parte do acervo foi marcada como lida sem registrar a data, o topo
 * da página seria justamente o que não tem informação nenhuma. Sem data,
 * desempata por título.
 */
export async function fetchLidos(userId: string): Promise<LivroDaEstante[]> {
    return withUser(userId, (tx) =>
        tx
            .select(colunasDaEstante)
            .from(books)
            .leftJoin(bookToAuthor, eq(books.id, bookToAuthor.bookId))
            .leftJoin(authors, eq(bookToAuthor.authorId, authors.id))
            .where(eq(books.read_status, 'lido'))
            .groupBy(books.id)
            .orderBy(sql`${books.date_finished} desc nulls last`, books.title)
    );
}

/** O que foi largado no meio. Ordem alfabética, como as demais estantes. */
export async function fetchAbandonados(
    userId: string
): Promise<LivroDaEstante[]> {
    return withUser(userId, (tx) =>
        tx
            .select(colunasDaEstante)
            .from(books)
            .leftJoin(bookToAuthor, eq(books.id, bookToAuthor.bookId))
            .leftJoin(authors, eq(bookToAuthor.authorId, authors.id))
            .where(eq(books.read_status, 'abandonado'))
            .groupBy(books.id)
            .orderBy(books.title)
    );
}
```

(`sql`, `eq`, `books`, `authors`, `bookToAuthor` e `withUser` já estão importados no topo do arquivo — nenhum import novo.)

Criar `app/(main)/leituras/page.tsx`:

```tsx
import Link from 'next/link';
import { BookmarkIcon, BookXIcon } from 'lucide-react';
import { getCurrentUserId } from '@/lib/auth-user';
import { fetchAbandonados, fetchLidos } from '@/lib/db/queries';
import { Estante } from '@/components/estante';
import { cn } from '@/lib/utils';

const ABAS = [
  { id: 'lidos', label: 'Lidos' },
  { id: 'abandonados', label: 'Abandonados' },
] as const;

type Aba = (typeof ABAS)[number]['id'];

// A URL é editável à mão: um valor torto cai no default em vez de dar 404,
// mesmo princípio que `paginaValida` já usa para o número de página.
function abaValida(entrada: unknown): Aba {
  return entrada === 'abandonados' ? 'abandonados' : 'lidos';
}

export default async function LeiturasPage(props: {
  searchParams: Promise<Record<string, string | string[] | undefined>>;
}) {
  const searchParams = await props.searchParams;
  const aba = abaValida(searchParams.aba);
  const userId = await getCurrentUserId();

  // Só a lista da aba ativa é buscada: abas no cliente exigiriam trazer as
  // duas para mostrar uma.
  const livros =
    aba === 'abandonados'
      ? await fetchAbandonados(userId)
      : await fetchLidos(userId);

  const plural = livros.length === 1 ? 'livro' : 'livros';

  return (
    <div className="p-4 space-y-4">
      <div>
        <h1 className="font-display text-2xl font-semibold tracking-tight">
          Leituras
        </h1>
        <p className="text-sm text-muted-foreground">
          {aba === 'abandonados'
            ? `${livros.length} ${plural} que você largou no meio.`
            : `${livros.length} ${plural} que você já terminou.`}
        </p>
      </div>

      {/* Mesmas classes de item ativo que a fileira do nav-bar usa, para não
          inventar um terceiro estilo de seleção no app. */}
      <nav className="flex gap-1.5" aria-label="Abas de leituras">
        {ABAS.map((item) => (
          <Link
            key={item.id}
            href={`/leituras?aba=${item.id}`}
            aria-current={aba === item.id ? 'page' : undefined}
            className={cn(
              'rounded-md px-2.5 py-1.5 text-sm font-medium transition-colors',
              aba === item.id
                ? 'bg-accent text-accent-foreground'
                : 'text-muted-foreground hover:bg-accent/50 hover:text-foreground'
            )}
          >
            {item.label}
          </Link>
        ))}
      </nav>

      <Estante
        livros={livros}
        icone={aba === 'abandonados' ? BookXIcon : BookmarkIcon}
        vazio={
          aba === 'abandonados'
            ? 'Nenhum livro abandonado — o que é uma boa notícia. Marcar um '
              + 'livro como "Abandonado" na página dele o traz para cá.'
            : 'Nenhum livro lido ainda. Marcar um livro como "Lido" na '
              + 'página dele o traz para cá.'
        }
      />
    </div>
  );
}
```
